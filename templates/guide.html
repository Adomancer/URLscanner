Guide

How the scanner works

What it checks, what the verdicts mean, and exactly what does (and does not) leave your machine.

Quick start

  1. Scan a link: paste it on the Scan page. Defanged forms such as hxxps://evil[.]com work.
  2. Check an e-mail: in Gmail open the message, choose ⋮ → Download message, and drop the .eml file on the Scan page.
  3. Watch your whole inbox: connect Gmail (see below) and use the Mail page or python cli.py gmail watch.

Reading the verdicts

Threat risk (0–100) answers “is this phishing or malware?”. Every finding carries a weight and they combine like independent probabilities: risk = 1 − Π(1 − weight). Two medium signals therefore add up to more than either alone, but never past 100.

Unverified means the link was analysed without contacting the site (as for every link in an e-mail): nothing bad was found, but nothing was proven either. Security grade (A+–F) is separate: how well a site is hardened (TLS, headers, DNS). A phishing page can have an A, and a good bank site can have a C.

A score is evidence, not a guarantee. Open the findings to see why; a real bank will never ask for your OTP, PIN or password by e-mail, whatever the score says.

Privacy

  • No third-party scanning service (VirusTotal, urlscan, …) and no API key, ever.
  • A normal URL scan contacts the site itself plus DNS (port 53) and WHOIS (port 43).
  • Every address, including each redirect hop, must be public: internal networks and cloud metadata are refused.
  • Links found in e-mail are never opened unless you ask for a deep scan of one message.

Gmail scanner

  1. Turn on 2-Step Verification for your Google account.
  2. Create an App Password at myaccount.google.com/apppasswords (name it “URL Scanner”).
  3. Put it in .env next to cli.py:
    GMAIL_ADDRESS=you@gmail.com
GMAIL_APP_PASSWORD=abcd efgh ijkl mnop
SCANNER_ACCESS_TOKEN=pick-a-long-random-string
  4. Run python cli.py gmail test, then a read-only first pass: python cli.py gmail scan --days 3 --no-label.

What it does to your mailbox

  • Reads with BODY.PEEK[] from a folder opened read-only: messages stay unread, nothing is moved or deleted.
  • Optionally adds URLscanner/Suspicious or URLscanner/Dangerous labels (separate connection, only its own labels; --no-label turns it off).
  • Stores a redacted summary only: no message bodies, and every URL has its query string and token-like parts masked.
An App Password gives full access to the mailbox. Keep it only in .env, never commit it, and revoke it on the same Google page when you stop using the scanner.

Trusted senders

Add addresses or domains to scanner/data/mail_allowlist.txt to never label them. It only applies when Gmail reports DMARC pass for a matching From domain, so a forged sender cannot use it.

Command line

python cli.py scan example.com --format html,sarif   # one URL (or a .txt of URLs)
python cli.py extract message.eml --scan            # score an e-mail file
python cli.py gmail scan --days 7                   # analyse + label recent mail
python cli.py gmail scan --folder spam --no-label --all
python cli.py gmail list -v                         # what was scanned
python cli.py gmail deep <id> --url 2              # open one message's link #2
python cli.py gmail watch --interval 300            # keep checking; Windows toast
python cli.py gmail eval outputs/labeled            # precision / recall on your mail
python tools/update_feeds.py                        # refresh offline threat feeds

Threat feeds

python tools/update_feeds.py downloads the OpenPhish community feed and, with a free ABUSECH_AUTH_KEY, URLhaus. These are bulk downloads compared locally: no scanned URL is ever sent to them. You can also drop your own lists (URLs, domains, IPs, hosts-file format) into scanner/data/blocklists/.

FAQ

A real newsletter was flagged. Open it and read the findings; a sender in the allowlist is never labelled. Measure your own false-positive rate with gmail eval.

Why are some links “Not analysed”? Each message has a 60-second budget and at most 30 links, so one hostile e-mail cannot stall the scanner.

The Mail page says 403. It shows your mail, so it needs SCANNER_ACCESS_TOKEN and only answers on localhost (add other host names to SCANNER_ALLOWED_HOSTS).

Gmail login fails. Use an App Password (not your normal password) created for the same account as GMAIL_ADDRESS. Work or school accounts may have IMAP or App Passwords turned off by their administrator.
